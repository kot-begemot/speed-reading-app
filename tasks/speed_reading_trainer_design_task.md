# Задача для дизайна и имплементации: тренажер скорочтения

## Контекст текущего приложения

Приложение `speed-reading-app` уже реализует базовый RSVP-ридер:

- библиотека книг и импорт файлов/ссылок;
- экран чтения с центральным показом слова или группы слов;
- настройка WPM, размера шрифта, количества слов за один тик;
- нижняя панель исходного текста с подсветкой текущего слова;
- сохранение прогресса чтения по книге;
- настройки темы, типографики и цветов.

Новый тренажер нужно добавлять как отдельный раздел поверх текущей архитектуры, а не как замену ридера. Часть упражнений может переиспользовать уже существующие механики: таймер WPM, токенизацию текста, группировку слов, настройки чтения и экран результата.

## Оценка разумности исходной задачи

Идея разумная: набор упражнений покрывает основные практические навыки скорочтения - периферийное восприятие, RSVP, распознавание слов, чтение группами, ведение темпа и проверку понимания.

Но в исходной постановке есть ограничения, которые важно учесть до дизайна и разработки:

- Количество фиксаций на строку и регрессии взгляда нельзя честно измерить на обычном телефоне без eye-tracking. В MVP это должны быть прокси-метрики: размер чанка, количество подсвеченных блоков на строку, ручные возвраты, паузы, скорость прохождения и понимание.
- Упражнение "считать 1-2-3 вслух" нельзя надежно проверять без микрофона и распознавания речи. В MVP это инструкция/режим с визуальным или звуковым метрономом, но не автоматический гейт.
- Понимание можно измерять только на текстах с заранее подготовленными вопросами. Для MVP нужны встроенные тренировочные тексты с 5 вопросами каждый. Для импортированных книг проверку понимания лучше оставить на будущий этап или сделать ручной self-check без влияния на уровень.
- Повышение уровня должно зависеть не от одного удачного упражнения, а от серии квалифицированных сессий: WPM достигнут, понимание не ниже порога, результат повторен несколько раз подряд.
- Главная метрика должна быть не чистый WPM, а эффективная скорость: `WPM * comprehensionRate`. Это защищает от "разгона без смысла".

## Цель продукта

Добавить в приложение раздел `Trainer`, который сначала проводит обязательную диагностику, определяет стартовый уровень пользователя, а затем дает доступ к тренировкам по выбранному языку. Повышение уровня возможно только при сохранении понимания текста.

## Короткая структура продукта

Тренажер делится на четыре слоя:

1. `Baseline Assessment`: обязательная диагностика по выбранному языку.
2. `Skill Training`: свободные дриллы отдельных навыков, например слежение за цифрами, таблицы Шульте, периферийное восприятие, флеш-распознавание.
3. `Training Program`: планомерная цепочка упражнений и тестов, где пользователь читает тексты выбранного языка и отвечает на вопросы.
4. `Content Library`: большие пулы текстов, вопросов, слов и числовых паттернов по языкам, с анти-повтором.

Главное правило: skill drills тренируют механику, но уровень повышается только через программу с текстом и проверкой понимания.

## Основной пользовательский сценарий

1. Пользователь открывает приложение.
2. Видит новый раздел `Trainer` рядом с библиотекой.
3. При первом входе выбирает язык диагностики и проходит базовую диагностику.
4. Получает стартовый уровень, целевой WPM и минимальный порог понимания для выбранного языка.
5. После диагностики выбирает один из двух режимов: `Skill Training` или `Training Program`.
6. В `Skill Training` тренирует отдельные навыки: слежение за цифрами, таблицы Шульте, периферию, флеш-распознавание, чанкинг.
7. В `Training Program` проходит планомерную цепочку упражнений и тестов на подготовленных текстах выбранного языка.
8. После текстовых упражнений отвечает на вопросы по прочитанному.
9. Получает результат: WPM, понимание, effective WPM, успешность сессии, прогресс уровня.
10. Возвращается позже и видит историю, графики и личные рекорды.

## Навигация верхнего уровня

Текущий `LibraryScreen` остается основным экраном для книг. Нужно добавить понятную навигацию к тренажеру.

Рекомендуемый вариант для дизайна:

```text
Bottom navigation:
Library | Trainer | Progress | Settings
```

Альтернатива, если дизайнер не хочет менять каркас приложения:

```text
Library app bar:
[Speed Reader]                         [Trainer] [Settings]
```

Предпочтение: нижняя навигация, потому что тренажер становится равноправной основной частью приложения, а не вторичной настройкой.

## MVP и дальнейшие этапы

### MVP

Для первой рабочей версии тренажера:

- `Trainer Home`;
- базовая диагностика;
- раздел `Skill Training`;
- раздел `Training Program`;
- общий экран выполнения упражнения;
- слежение за цифрами;
- таблицы Шульте;
- RSVP-тренировка с тестом понимания;
- флеш-распознавание слов/фраз;
- чанкинг/чтение блоками;
- ведение темпа подсветкой;
- экран вопросов на понимание;
- экран результата с WPM, пониманием, effective WPM и гейтом уровня;
- базовый экран прогресса;
- локальное сохранение истории тренировок.

### Post-MVP

- реальные или AI-сгенерированные вопросы по импортированным книгам;
- микрофон для контроля упражнения против субвокализации;
- более детальная аналитика по слабым навыкам;
- экспорт прогресса;
- синхронизация между устройствами;
- eye-tracking, если когда-нибудь появится техническая основа.

## Страницы и функциональность

### 1. App Shell / Главная навигация

Назначение: дать доступ к существующей библиотеке, тренажеру, прогрессу и настройкам.

Функции:

- нижняя навигация или другой постоянный способ перехода между `Library`, `Trainer`, `Progress`, `Settings`;
- сохранение текущего состояния вкладок;
- бейдж на `Trainer`, если диагностика не пройдена или есть незавершенная сессия;
- бейдж на `Progress`, если пользователь побил личный рекорд.

Состояния:

- первый запуск без диагностики;
- обычное состояние;
- активная незавершенная тренировка;
- нет доступного контента для выбранного языка.

### 2. Trainer Home / Вход в тренажер

Назначение: основной вход в тренажер.

Главные элементы:

- статус диагностики;
- выбранный язык тренировки;
- селектор языка;
- карточка текущего уровня;
- целевой WPM уровня;
- минимальный процент понимания;
- текущая серия успешных сессий подряд;
- личный рекорд effective WPM;
- кнопка `Start baseline assessment`, если диагностика не пройдена;
- кнопка `Skill Training`, если диагностика пройдена;
- кнопка `Training Program`, если диагностика пройдена;
- быстрые карточки упражнений;
- краткая история последних 3-5 тренировок.

Первый запуск:

- главным действием показывать `Baseline assessment`;
- не показывать обычные тренировки как основной сценарий до завершения диагностики;
- объяснить, что уровень будет подобран по скорости и пониманию для выбранного языка.

После диагностики:

- пользователь может выбрать язык тренировки;
- пользователь может выбрать свободный skill drill;
- пользователь может запустить планомерную программу упражнений;
- если для выбранного языка нет подготовленных тестов, показать недоступное состояние и предложить другой язык.

Для пользователя после провала:

- показывать, что уровень не потерян, но серия успешных сессий сброшена;
- предлагать повторить тренировку или снизить скорость на следующей сессии.

### 3. Baseline Assessment / Базовая диагностика

Назначение: определить стартовый уровень пользователя.

Сценарий:

1. Пользователь выбирает язык диагностики.
2. Короткий интро-экран объясняет, что диагностика обязательна перед тренировками.
3. Пользователь читает подготовленный текст на выбранном языке.
4. Приложение измеряет время чтения.
5. Пользователь отвечает на 5 вопросов по прочитанному.
6. Приложение считает WPM, понимание и effective WPM.
7. Пользователь получает стартовый уровень и рекомендацию для выбранного языка.

Главные элементы:

- language selector;
- прогресс диагностики;
- текст для чтения;
- кнопка `I'm done reading`;
- экран вопросов;
- результат диагностики.

Метрики:

- raw WPM;
- comprehension percent;
- effective WPM;
- suggested level.

Требования к контенту:

- минимум 3 диагностических текста по 300-600 слов на каждый поддерживаемый язык;
- каждый текст должен иметь 5 вопросов с 4 вариантами ответа;
- тексты должны быть нейтральной сложности, без специальных знаний.

Важно:

- baseline должен храниться отдельно по языкам;
- если пользователь выбирает новый язык тренировки, где baseline еще не пройден, сначала нужно пройти диагностику для этого языка;
- уровень по одному языку нельзя автоматически переносить на другой.

### 4. Training Language Selection / Выбор языка тренировки

Назначение: дать пользователю выбрать язык, на котором будут упражнения, тексты и вопросы.

Где используется:

- перед baseline;
- на `Trainer Home`;
- перед запуском упражнения;
- в фильтрах истории и прогресса.

Элементы:

- список поддерживаемых языков;
- состояние `baseline completed` / `baseline required`;
- количество доступных текстов и тестов для языка;
- предупреждение, если пул текстов почти исчерпан;
- выбор языка по умолчанию.

Правила:

- упражнение с текстом запускается только на языке, где есть подготовленный контент;
- если baseline для языка не пройден, первое действие - диагностика;
- история результатов, уровень и рекорды должны фильтроваться по языку;
- повторные тексты не должны выдаваться, пока в пуле есть неиспользованные подходящие тексты.

### 5. Skill Training и Training Program / Навыки и программа

Назначение: разделить тренажер на свободную тренировку отдельных навыков и планомерную программу тестов/упражнений.

#### Skill Training

Это быстрые drill-упражнения на отдельные механики. Они могут улучшать рекомендации и статистику, но сами по себе не должны повышать уровень чтения без проверки понимания.

Упражнения:

- Number Tracking;
- Schulte Table;
- Peripheral Vision;
- Flash Recognition;
- Chunk Reading;
- Pacer mechanics без обязательного comprehension gate.

Правила:

- можно запускать свободно после baseline;
- можно делать practice-only;
- сессии короткие, 1-5 минут;
- результат сохраняется как навык, но не заменяет текстовый тест понимания;
- язык нужен только там, где используются слова/фразы.

#### Training Program

Это планомерный набор упражнений и тестов для роста уровня. Программа использует подготовленные тексты выбранного языка и всегда заканчивается comprehension test, если упражнение текстовое.

Состав программы:

- текстовый RSVP;
- chunk reading на тексте;
- pacer reading;
- comprehension test;
- периодические контрольные тесты уровня.

Правила:

- запускается после baseline выбранного языка;
- использует тексты из пула языка и уровня;
- не повторяет текст, пока есть неиспользованные;
- повышает уровень только через qualified-сессии;
- может рекомендовать skill drills, если видно слабое место.

Карточка упражнения:

- название;
- короткое назначение;
- иконка;
- сложность/уровень;
- лучший результат;
- последний результат;
- состояние `available`, `recommended`, `locked`, `completed`;
- язык, если упражнение зависит от текста или словаря;
- кнопка запуска.

Фильтры/сегменты:

- `Program`;
- `Skills`;
- `Recommended`;
- `All`;
- `Weak skills`;
- `Completed`.

### 6. Training Program Plan / План программы

Назначение: показать пользователю последовательность упражнений и тестов после диагностики.

Главные элементы:

- выбранный язык;
- текущий уровень;
- цель уровня: WPM и comprehension threshold;
- список шагов программы;
- какие шаги уже пройдены;
- следующий рекомендуемый шаг;
- сколько successful sessions нужно до повышения уровня;
- кнопка `Start next step`;
- кнопка `Practice weak skill`, если программа рекомендует отдельный drill.

Типы шагов:

- `Skill warm-up`: Schulte, Number Tracking или Peripheral Vision;
- `Recognition drill`: Flash Recognition;
- `Text exercise`: RSVP, Chunk Reading или Pacer Reading;
- `Comprehension test`;
- `Level checkpoint`.

Правила:

- warm-up и recognition drill помогают подготовиться, но не обязаны быть гейтом уровня;
- text exercise + comprehension test являются главным гейтом;
- если пользователь проваливает понимание, программа рекомендует повторить текстовый шаг с меньшей скоростью;
- если пользователь проваливает внимательность/поиск, программа рекомендует Number Tracking или Schulte.

### 7. Exercise Intro / Настройка перед упражнением

Назначение: объяснить упражнение и дать пользователю контроль сложности перед стартом.

Общие элементы:

- название упражнения;
- что тренирует;
- цель сессии;
- длительность;
- текущая сложность;
- условия успешного прохождения;
- кнопка `Start`;
- опциональная кнопка `Practice without saving`.

Настройки по типам:

- WPM;
- длительность;
- размер сетки;
- время показа;
- размер чанка;
- язык тренировки;
- источник текста;
- включить/выключить звук метронома;
- включить/выключить вибрацию.

### 8. Exercise Runtime Shell / Общий экран выполнения упражнения

Назначение: единый каркас для всех упражнений, чтобы тренажер ощущался цельным.

Общие элементы:

- верхняя строка: название, уровень, таймер;
- центральная зона упражнения;
- нижняя зона: прогресс, пауза, перезапуск, выход;
- состояние `3-2-1 countdown`;
- состояние паузы;
- состояние завершения;
- состояние ошибки/сбоя контента.

Важно для дизайна:

- экран должен быть минималистичным, без лишнего текста во время упражнения;
- управляющие элементы не должны мешать фиксации взгляда;
- все активные зоны должны быть удобны для большого пальца на телефоне;
- упражнения должны работать в портретной ориентации; landscape можно поддержать позже.

### 9. Schulte Table / Таблицы Шульте

Назначение: тренировать периферийное восприятие и поиск объектов без лишних движений глаз.

Механика:

- сетка с числами от 1 до N;
- пользователь нажимает числа по порядку;
- текущая цель отображается компактно;
- таймер стартует при первом тапе или после countdown;
- ошибки подсвечиваются, но не ломают сессию;
- после завершения показывается время и ошибки.

Сложность:

- уровень 1: 3x3;
- уровень 2: 4x4;
- базовый стандарт: 5x5;
- advanced: 6x6 и больше.

Минимальный ориентир:

- таблица 5x5 за 40 секунд или быстрее;
- ошибок: 0-2, иначе результат не считается идеальным.

Метрики:

- total time;
- errors;
- average tap interval;
- best 5x5 time;
- pass/fail.

Экран результата:

- время;
- лучший результат;
- сравнение с прошлой попыткой;
- рекомендация: повторить, усложнить, перейти дальше.

### 10. Number Tracking / Слежение за цифрами

Назначение: тренировать внимание, контроль взгляда, поиск последовательностей и устойчивость к визуальному шуму.

Механика:

- на экране появляются цифры или короткие числовые последовательности;
- пользователь должен следить за заданной цифрой, маршрутом или порядком чисел;
- варианты режимов: `find next`, `follow moving number`, `tap sequence`, `remember path`;
- часть цифр может двигаться, исчезать или меняться местами;
- после серии пользователь выбирает правильный ответ или нажимает числа в нужном порядке.

Режимы:

- `Static sequence`: найти 1-2-3-4 на поле с отвлекающими цифрами;
- `Moving target`: следить за одной цифрой среди движущихся отвлекающих;
- `Trail memory`: запомнить путь цифры и восстановить его;
- `Peripheral numbers`: цифры появляются вокруг центра, взгляд фиксируется в середине.

Сложность:

- количество цифр на экране;
- скорость движения;
- время показа;
- количество отвлекающих элементов;
- длина последовательности;
- размер поля.

Метрики:

- accuracy;
- reaction time;
- sequence completion time;
- mistakes;
- lost target count;
- best level per mode.

Правила:

- упражнение относится к `Skill Training`;
- само по себе не повышает уровень чтения;
- может быть рекомендовано программой, если пользователь часто ошибается в поиске, темпе или удержании внимания.

### 11. Peripheral Vision / Расширение поля зрения

Назначение: тренировать распознавание слов/чисел в периферии при фиксации взгляда в центре.

Механика:

- в центре фиксатор: точка, крест или короткое слово;
- вокруг центра в разных позициях появляются слова/числа;
- пользователь должен распознать стимул и выбрать ответ;
- варианты ответа можно показывать снизу после исчезновения стимула;
- радиус появления и скорость постепенно растут.

Важное ограничение:

- приложение не может проверить, что взгляд реально был зафиксирован в центре. Это упражнение строится на инструкции и честном выполнении.

Сложность:

- количество позиций: 4 -> 8 -> 12;
- длительность показа: 800 ms -> 500 ms -> 300 ms -> 200 ms;
- тип стимулов: цифры -> короткие слова -> пары слов;
- расстояние от центра: ближе -> дальше.

Метрики:

- accuracy;
- reaction time;
- максимальный радиус с точностью не ниже 80%;
- количество серий подряд без ошибок.

Успех:

- точность не ниже 80% на текущей сложности.

### 12. Anti-subvocalization RSVP / Подавление субвокализации

Назначение: помочь пользователю читать быстрее внутреннего проговаривания.

Механика:

- слова показываются по одному или группами в центре, как в существующем RSVP-ридере;
- скорость задается уровнем пользователя;
- текст выбирается из пула выбранного языка;
- включается вспомогательный ритм: визуальный метроном или звук;
- опциональная инструкция: вслух считать "1-2-3" во время чтения;
- после текста пользователь проходит тест на понимание.

Что использовать из текущего приложения:

- `ReaderEngine`;
- `FocusWordView`;
- WPM settings;
- words per entry;
- central letter highlight.

Ограничение:

- в MVP приложение не проверяет голосом, что пользователь действительно считает. Это не должно быть условием автоматического прохождения.

Метрики:

- target WPM;
- фактическая длительность;
- completion percent;
- pauses;
- comprehension percent;
- effective WPM.

Минимальный ориентир:

- 300 WPM с пониманием не ниже 60% для среднего уровня;
- для гейта использовать таблицу уровней ниже.

### 13. Flash Recognition / Скорость распознавания

Назначение: тренировать быстрое узнавание слова или короткой фразы.

Механика:

- на экране кратко появляется слово или фраза;
- затем показывается маска или пустой экран;
- пользователь выбирает правильный вариант из 3-4 ответов или вводит ответ;
- время показа сокращается при успехе;
- длина фразы растет: 1 слово -> 2 слова -> 3 слова.

Контент:

- слова и фразы берутся из словаря выбранного языка;
- фразы не должны повторяться в рамках одной сессии;
- словари должны иметь уровни сложности.

Сложность:

- 500 ms;
- 400 ms;
- 300 ms;
- 200 ms;
- 100 ms для advanced.

Минимальный ориентир:

- распознавание фраз из 3 слов за 300 ms или быстрее;
- точность не ниже 70%.

Метрики:

- exposure time;
- phrase length;
- accuracy;
- series of correct answers;
- best exposure time at 70%+ accuracy.

### 14. Chunk Reading / Чтение блоками

Назначение: тренировать чтение группами слов вместо пословного чтения.

Механика:

- текст разбит на чанки по 2-4 слова;
- чанки подсвечиваются последовательно;
- пользователь читает строку по блокам;
- после отрывка пользователь отвечает на вопросы.

Контент:

- текст выбирается из пула выбранного языка и текущего уровня;
- повтор текста запрещен, пока есть неиспользованные тексты того же языка и уровня.

Прокси для "2 фиксации на строку":

- приложение не измеряет реальные фиксации;
- вместо этого оно считает количество подсвеченных чанков на строку;
- цель уровня может быть: строка проходится за 2-3 чанка без падения понимания.

Настройки:

- words per chunk: 2, 3, 4;
- WPM;
- highlight mode: block, underline, moving window;
- text width/line length.

Метрики:

- chunk size;
- chunks per line;
- WPM;
- pauses/manual regressions;
- comprehension percent.

Успех:

- пройти отрывок на целевом WPM;
- понимание не ниже порога уровня;
- без чрезмерного количества ручных возвратов.

### 15. Pacer Reading / Ведение указателем

Назначение: тренировать удержание темпа на обычном тексте.

Механика:

- показывается страница текста;
- подсветка, линия или маркер движется по словам/строкам с заданной скоростью;
- пользователь следует глазами за подсветкой;
- скорость можно подобрать до старта, но во время квалифицированной сессии она фиксирована;
- после страницы идет тест понимания.

Контент:

- текст выбирается по языку, уровню и длине;
- вопросы должны относиться именно к прочитанному отрывку.

Минимальный ориентир:

- удержание темпа 400 WPM на всей странице;
- понимание не ниже порога уровня.

Метрики:

- target WPM;
- actual WPM;
- completed percent;
- pauses;
- manual rewind count;
- comprehension percent;
- effective WPM.

Состояния:

- countdown;
- active reading;
- paused;
- completed;
- failed because user exited early;
- completed but not qualified because comprehension is too low.

### 16. Comprehension Test / Проверка понимания

Назначение: не дать пользователю повышать скорость без сохранения смысла.

Механика:

- после текстового упражнения показываются 5 вопросов;
- вопрос с 4 вариантами ответа;
- один правильный ответ;
- можно вернуться к предыдущему вопросу до отправки;
- после отправки показывается результат.

Правила:

- результат сессии засчитывается только после прохождения теста;
- в квалификационных сессиях нельзя открывать исходный текст во время ответов;
- понимание считается как `correctAnswers / totalQuestions * 100`.

Языки:

- вопросы показываются на языке текста;
- варианты ответа должны быть заранее подготовлены вместе с текстом;
- нельзя использовать один и тот же тест повторно, пока есть неиспользованные тесты выбранного языка и уровня.

Состояния:

- вопрос без ответа;
- выбран ответ;
- ошибка валидации, если пользователь пытается отправить без ответа;
- результат;
- обзор ответов после завершения.

### 17. Session Result / Результат сессии

Назначение: ясно показать, что получилось и засчиталась ли тренировка.

Главные элементы:

- статус: `Qualified`, `Not qualified`, `Practice only`;
- WPM;
- язык тренировки;
- comprehension percent;
- effective WPM;
- цель уровня;
- минимальное понимание уровня;
- успешные сессии подряд;
- прогресс до следующего уровня;
- лучший результат пользователя;
- кнопки `Continue training`, `Repeat`, `View progress`.

Правила успеха:

- `WPM >= level.targetWpm`;
- `comprehensionPercent >= level.minComprehension`;
- текстовое упражнение завершено;
- сессия не была отмечена как practice-only.

Если провал:

- показать конкретную причину: скорость ниже цели, понимание ниже порога, сессия не завершена;
- серия успешных сессий подряд сбрасывается;
- effective WPM все равно сохраняется в историю.

### 18. Level Progression / Уровни и гейты

Назначение: сделать систему роста прозрачной.

Таблица уровней:

| Level | Target WPM | Min comprehension | Promotion condition |
|---|---:|---:|---|
| 1 | 200 | 70% | 3 successful sessions in a row |
| 2 | 250 | 70% | 3 successful sessions in a row |
| 3 | 300 | 65% | 3 successful sessions in a row |
| 4 | 400 | 65% | 5 successful sessions in a row |
| 5 | 500 | 60% | 5 successful sessions in a row |
| 6+ | +100 per level | 60% | 5 successful sessions in a row |

Правила:

- уровень повышается только после нужного количества успешных сессий подряд;
- провал сбрасывает счетчик подряд успешных сессий;
- порог понимания не опускается ниже 60%;
- уровень, серия успешных сессий и baseline хранятся отдельно для каждого языка;
- упражнения на распознавание и таблицы Шульте улучшают навыки, но повышение уровня должно зависеть от текстовой сессии с comprehension test.

Визуальные элементы:

- текущий уровень;
- следующая цель;
- прогрессбар успешных сессий подряд;
- история последних попыток;
- список разблокированных сложностей.

### 21. Training Text Library / Тренировочные тексты

Назначение: управлять контентом, на котором проверяется понимание.

MVP:

- встроенные тексты внутри приложения;
- поддержка нескольких языков;
- у каждого текста есть язык, уровень сложности, количество слов, тема и 5 вопросов;
- целевой пул: минимум 100 текстов-тестов на каждый поддерживаемый язык;
- каждый текст-тест включает сам текст, 5 вопросов, 4 варианта ответа на вопрос и правильный ответ;
- текст не повторяется, пока для выбранного языка и уровня есть неиспользованные тексты.

Экран может быть скрытым или простым в MVP, но дизайнеру нужно предусмотреть состояния:

- выбор языка;
- выбор текста перед свободной тренировкой;
- список доступных текстов;
- текст уже использовался недавно;
- недостаточно новых текстов для уровня.

Правила анти-повтора:

- хранить `usedTextIds` по пользователю, языку и уровню;
- при выборе текста сначала брать неиспользованные тексты нужного языка и уровня;
- если пул исчерпан, разрешить повтор только после явного состояния `all texts used`;
- при повторе выбирать самый давно использованный текст;
- не показывать один и тот же текст два раза подряд;
- вопросы должны повторяться только вместе с соответствующим текстом.

Импорт/загрузка контента:

- нужен формат для загрузки пачки текстов и вопросов, например JSON;
- импорт должен валидировать язык, уровень, длину текста, количество вопросов и количество вариантов;
- некорректные тексты не должны попадать в тренировочный пул;
- дизайнеру нужно предусмотреть технический/админский экран или хотя бы состояния загрузки контента, если это будет не только bundled assets.

Минимальная структура контент-пака:

```text
TrainingContentPack {
  languageCode
  version
  texts: [
    {
      id
      title
      level
      topic
      wordCount
      body
      questions: [
        {
          prompt
          options[4]
          correctOptionIndex
          explanation?
        }
      ]
    }
  ]
}
```

Правила валидации:

- `languageCode` обязателен и должен совпадать у всех текстов внутри пака;
- в каждом тексте должно быть ровно 5 вопросов;
- у каждого вопроса должно быть ровно 4 варианта ответа;
- `correctOptionIndex` должен указывать на существующий вариант;
- `wordCount` должен совпадать с фактическим количеством слов или пересчитываться при импорте;
- `id` текста должен быть стабильным, чтобы анти-повтор работал после обновления контент-пака.

Post-MVP:

- импорт отрывка из книги пользователя;
- генерация вопросов;
- ручное добавление вопросов;
- отметка текста как слишком легкого/сложного.

## Метрики

### WPM

```text
WPM = wordCount / readingSeconds * 60
```

Паузы:

- для обычной практики можно исключать паузы;
- для квалификационной сессии лучше считать общее активное время чтения, но не время на вопросы;
- если пользователь часто ставит паузу, это сохраняется как отдельная метрика.

### Comprehension

```text
comprehensionPercent = correctAnswers / totalQuestions * 100
```

### Effective WPM

```text
effectiveWpm = WPM * (comprehensionPercent / 100)
```

### Successful sessions in row

Это отдельный счетчик для повышения уровня. Увеличивается только при qualified-сессии. Сбрасывается при провале квалификационной сессии.

## Логика тренировочной сессии

Есть два типа сессий.

### Skill Training Session

Назначение: быстро тренировать отдельный навык без обязательной проверки понимания.

Примеры:

1. Number Tracking, 1-3 минуты.
2. Schulte Table, 1-3 раунда.
3. Peripheral Vision, 1-3 минуты.
4. Flash Recognition, 10-30 попыток.

Правила:

- пользователь сам выбирает drill;
- сессия не обязана быть ежедневной;
- результат сохраняется в статистику навыков;
- уровень чтения не повышается только за счет skill drill;
- программа может рекомендовать drill как подготовку к следующему текстовому шагу.

### Training Program Session

Назначение: планомерно вести пользователя от диагностики к росту уровня через связку упражнений и тестов.

Рекомендуемый состав:

1. `Skill warm-up`: Number Tracking, Schulte или Peripheral Vision, 1-2 минуты.
2. `Recognition drill`: Flash Recognition или Chunk Reading, 2-3 минуты.
3. `Text exercise`: RSVP, Chunk Reading или Pacer Reading на тексте выбранного языка.
4. `Comprehension Test`: 5 вопросов по прочитанному.
5. `Result screen`: WPM, comprehension, effective WPM, pass/fail.

Правила:

- запускается после baseline выбранного языка;
- использует подготовленные тексты и вопросы выбранного языка;
- приложение не должно навязывать "сегодняшнюю тренировку" как основной сценарий;
- программа может предлагать следующий шаг, но пользователь видит всю цепочку;
- qualified-сессия засчитывается только через текстовый шаг и comprehension test.

Длительность MVP program-сессии: 5-10 минут.

## Логика адаптивной сложности

После успешной сессии:

- немного повышать WPM или сложность упражнения;
- если серия успешных сессий достигла порога, повысить уровень.

После провала по пониманию:

- не повышать WPM;
- предложить повторить с той же скоростью или снизить темп;
- подсветить, что проблема не в скорости, а в понимании.

После провала по скорости:

- оставить уровень;
- предложить короткие упражнения на распознавание и чанкинг.

После провала по поиску, вниманию или удержанию цели:

- не блокировать чтение;
- рекомендовать Number Tracking, Schulte или Peripheral Vision;
- не засчитывать эти drills как повышение уровня без текстового теста.

## Контент для MVP

Минимальный набор:

- минимум 3 текста для baseline на каждый поддерживаемый язык;
- минимум 100 тренировочных текстов-тестов на каждый поддерживаемый язык;
- тексты должны быть распределены по уровням сложности;
- по 5 вопросов на каждый текст;
- по 4 варианта ответа на каждый вопрос;
- словари слов/фраз для Flash Recognition на каждый язык;
- наборы чисел, маршрутов и паттернов для Number Tracking;
- наборы чисел/слов для Peripheral Vision на каждый язык, если упражнение использует слова.

Требования:

- тексты без специальных знаний;
- разные темы, чтобы пользователь не запоминал ответы;
- длина текста должна соответствовать уровню и длительности упражнения;
- вопросы должны проверять смысл, а не случайные детали;
- тексты и вопросы должны загружаться пачками и проходить валидацию;
- один и тот же текст не должен повторяться, пока есть неиспользованные тексты нужного языка и уровня.

## Требования к визуальному дизайну

- Следовать текущему стилю приложения: спокойный Material-like интерфейс, нейтральные карточки, аккуратные кнопки, поддержка light/dark.
- Тренировочные экраны должны быть чище и тише, чем экраны прогресса: минимум декоративных элементов, максимум фокуса.
- Не перегружать упражнение инструкциями во время выполнения. Инструкции - на intro-экране.
- Для успешности/ошибки использовать понятные состояния, но не агрессивные цвета.
- Все важные метрики должны быть читаемы на маленьком экране.
- Touch targets должны быть удобны для мобильного использования.
- Нужны макеты минимум для 390x844 и 430x932.
- В runtime-экранах предусмотреть safe area, нижнюю системную область и возможность скрытия controls.

## Edge cases

- Пользователь вышел во время упражнения.
- Пользователь закрыл приложение во время сессии.
- Нет подготовленных текстов для текущего уровня.
- Нет подготовленных текстов для выбранного языка.
- Пользователь выбрал язык, где baseline еще не пройден.
- Пул текстов выбранного языка и уровня исчерпан.
- Пользователь уже видел этот текст недавно.
- Пользователь прошел скорость, но провалил понимание.
- Пользователь прошел понимание, но скорость ниже цели.
- Пользователь хочет тренироваться без влияния на уровень.
- Пользователь выполняет skill drill, но не проходит text exercise.
- Пользователь сбрасывает прогресс тренажера.
- Очень маленький экран.
- Темная тема.
- Большой системный размер шрифта.

## Acceptance criteria

- В приложении появился раздел тренажера.
- Первый вход в тренажер предлагает выбрать язык и пройти baseline assessment.
- После baseline пользователю назначается уровень для выбранного языка.
- Пользователь может выбрать язык тренировки.
- После диагностики пользователь видит два режима: `Skill Training` и `Training Program`.
- Пользователь может запускать skill drills без влияния на повышение уровня.
- Пользователь может проходить планомерную программу упражнений и тестов.
- Каждое упражнение имеет intro, runtime и result state.
- Сессии сохраняются локально.
- WPM, comprehension и effective WPM считаются и отображаются одинаково во всех экранах.
- Уровень повышается только после нужного количества successful sessions in row.
- Уровень повышается только через text exercise + comprehension test, а не через отдельные skill drills.
- Провал понимания не засчитывает сессию для повышения уровня.
- Progress dashboard показывает WPM, comprehension, effective WPM и record с фильтром по языку.
- Контент-пул поддерживает минимум 100 текстов-тестов на язык.
- Тексты не повторяются, пока есть неиспользованные тексты выбранного языка и уровня.
- Дизайн покрывает пустые, успешные, провальные и locked-состояния.

## Открытые вопросы для дизайна/продукта

- Интерфейс тренажера делать на английском, как текущий app copy, или сразу локализовать на русский?
- Нужна ли нижняя навигация, или достаточно кнопки `Trainer` в текущей библиотеке?
- Какие языки поддерживаем в первой версии?
- Нужно ли блокировать advanced-упражнения до уровня пользователя или только помечать их как сложные?
- Нужны ли звуки/вибрация в MVP?
- 100 текстов-тестов нужно готовить на каждый язык целиком или на каждый язык и диапазон уровней?
- Контент будет только bundled assets или нужен импорт JSON-паков после релиза?
